# App 自动运营框架

可配置的 App 自动运营技能，支持招聘平台自动投递和社交平台自动运营两大场景。核心能力：智能打分筛选、多阶段任务编排、消息分类路由、隐私保护、状态追踪、异常通知。

## 前置条件

- 需要 `mobile_use`（云手机）能力来操作 App
- 需要 `calendar` 能力来定时触发任务
- 需要 `email` 能力来发送通知

如果云手机不可用，提示用户先添加云电脑/云手机设备。

## 核心工作流

### 第一步：确认任务类型

用户发起时先确认要执行哪种运营任务：

| 任务类型 | 触发关键词 | 说明 |
|---------|-----------|------|
| 求职投递 | 投递、投简历、找工作、Boss | 招聘平台自动浏览+投递+消息跟进 |
| 社交运营 | 代运营、聊天、打招呼、发动态 | 社交平台自动消息+互动+内容发布 |
| 自定义 | 用户自定义的App操作 | 基于模板创建新任务 |

### 第二步：加载或创建配置

检查是否有对应的配置文件存在：

- 求职投递 → 读取 `job_config.yaml`（参考 configs/job_config_template.yaml）
- 社交运营 → 读取 `social_config.yaml`（参考 configs/social_config_template.yaml）

如果没有配置文件，引导用户创建：
1. 确认运营的目标 App 名称
2. 确认筛选/匹配规则（如求职的薪资范围、城市；社交的人设信息）
3. 确认通知方式（邮箱/Webhook）
4. 将配置写入 `./autopilot_configs/` 目录

### 第三步：执行任务

根据任务类型，按以下流程执行。

## 场景一：求职自动投递

### 整体流程

```
读取配置 → 打分规则加载 → 阶段一：投递 → 阶段二：消息跟进 → 状态更新 → 通知用户
```

### 阶段一：岗位投递

1. **启动云手机**，打开目标 App
2. 进入职位浏览页面（底部"职位"入口）
3. 按配置的分类筛选（如"内容运营""新媒体运营"）
4. 对每个岗位执行打分：
   - 读取配置中的打分维度和权重
   - 逐项匹配：薪资范围、城市、岗位类型、经历匹配度、技能匹配度
   - 计算总分，与阈值比较
5. 达到投递阈值的岗位 → 点击"立即沟通"（或对应按钮）→ 返回列表继续
6. 达到每日目标数量后停止投递

**打分引擎工作方式：**

打分由配置文件定义维度，运行时逐项计算。示例打分结构：

```yaml
scoring:
  total_max: 110
  threshold: 60        # 低于此分不投递
  priority_threshold: 80  # 高于此分优先投递
  dimensions:
    - name: "薪资匹配"
      weight: 20
      rules:
        - condition: "最低薪资 >= 用户期望最低薪"
          score: 20
        - condition: "最低薪资 < 用户期望最低薪"
          score: 0
    - name: "城市匹配"
      weight: 10
      rules:
        - condition: "城市 in 用户目标城市列表"
          score: 10
    # ... 更多维度
```

执行打分时，对每个维度按 rules 条件判断，满足则加对应分数，最终求和。

**过滤规则（硬性排除）：**

即使总分达标，命中以下关键词的岗位也必须跳过：
```yaml
hard_filters:
  exclude_keywords:
    - "主播"
    - "带货"
    - "歌手"
    - "模特"
    - "销售"
    # ... 用户可自定义
```

### 阶段二：消息跟进

投递完成后**必须**执行消息跟进，不能省略：

1. 切换到"聊天"页面
2. 逐个检查未读消息
3. 对每条消息分类并处理：

| 消息类型 | 判断依据 | 处理方式 |
|---------|---------|---------|
| 索要简历 | 含"简历"/"发简历"等 | 自动点击"发简历"按钮发送 |
| HR提问 | 含问号、询问经历等 | **不自动回复**，通知用户自行回复 |
| 约面试 | 含"面试"/"约面"/"见面"等 | 通知用户 + 发邮件 |
| 加微信/电话 | 含"微信"/"加我"/"电话"等 | 通知用户 + 发邮件 |
| 明确拒绝 | 含"不合适"/"不匹配"等 | 通知用户 |
| 打招呼 | 系统/寒暄类 | 不回复不通知 |

**关键规则：严禁自动回复 HR 的问题。** 只自动发送简历文件，其他所有 HR 提问都通知用户自行处理。

### 去重机制

- 维护已投递岗位列表（公司名+岗位名）
- 每次投递前检查是否已投递过
- 已投递过的岗位直接跳过

## 场景二：社交平台自动运营

### 整体流程

```
读取配置 → 加载状态缓存 → 检查新消息 → 回复消息 → 打招呼新用户 → 发布内容 → 更新状态 → 检查停止条件
```

### 消息处理

1. 进入消息列表页面
2. 下滑查看所有对话
3. 对每个有新消息的对话：
   a. 先点击对方主页确认基本信息（性别等）
   b. 检查是否在排除名单中 → 是则跳过
   c. 查看聊天内容，按规则回复

**回复规则：**

```yaml
reply_rules:
  # 零回复规则：对方至少发了2-3条无回复才回复
  min_unreplied: 2
  # 回复风格
  style:
    max_length: 15          # 每条回复不超过15字
    no_emoji: true           # 不用emoji
    forbidden_words:         # 禁用称呼
      - "宝贝"
      - "亲爱的"
      - "乖乖"
    preferred_words:         # 推荐用这些称呼
      - "你"
  # 高意向信号（触发通知）
  high_intent_signals:
    - "见面"
    - "约"
    - "出来"
    - "要微信"
    - "加你"
```

### 打招呼（新用户）

1. 在推荐列表中寻找新用户
2. **每轮最多打招呼 3 人**（防止触发限流）
3. 打招呼前确认：
   - 不在排除名单中
   - 符合基本筛选条件
4. 使用配置中的打招呼话术

### 发布内容

1. 进入动态/朋友圈页面
2. 发布一条动态（内容从配置的动态池随机选取或生成）
3. **关闭定位**（找到位置标签的关闭按钮）
4. **不使用 emoji**

### 停止条件

```yaml
stop_conditions:
  # 连续发送2条消息零回复，停止主动联系该用户
  unreplied_limit: 2
  # 出现橙色箭头标记的不再发送
  orange_arrow_stop: true
  # 排除名单中的绝对不联系
  blocklist_strict: true
```

## 隐私保护规则

这是**最高优先级**的规则，违反会导致严重后果：

```yaml
privacy:
  # 运营身份（对外展示）
  public_identity:
    name: "你的昵称"
    age: "自定义"
    # ... 在配置文件中定义
  
  # 真实身份（严禁暴露）
  private_identity:
    real_name: "不要在任何对话中提及"
    phone: "不要在 any 对话中提及"
    qq: "不要在任何对话中提及"
    email: "不要在任何对话中提及"
  
  # 敏感信息释放条件
  release_rules:
    wechat:
      condition: "仅当对方主动索要时才提供"
      value: "在配置中定义"
```

执行过程中，每次发送消息前都要自检：是否暴露了真实身份信息？

## 状态管理

### 文件结构

在 `./autopilot_state/` 目录下维护状态文件：

```
autopilot_state/
├── job_applications.json    # 已投递岗位记录
├── contacts.json           # 联系人状态
├── blocklist.json          # 排除名单
└── daily_log.json          # 每日执行日志
```

### 状态格式

```json
// contacts.json 示例
{
  "contacts": {
    "user_001": {
      "name": "对方昵称",
      "platform_id": "平台用户ID",
      "status": "active",       // active/blocked/stale
      "last_message_time": "2026-01-01T10:00:00",
      "unreplied_count": 0,
      "notes": ""
    }
  },
  "blocklist": ["user_002", "user_003"],
  "last_updated": "2026-01-01T10:00:00"
}
```

每轮执行结束后**必须**更新状态文件。

## 通知系统

### 通知触发规则

```yaml
notifications:
  email:
    to: "user@example.com"
    triggers:
      - type: "interview"
        subject: "【自动运营通知】面试邀约 - {company_name}"
        include: ["公司名称", "岗位名称", "HR消息原文"]
      - type: "add_contact"
        subject: "【自动运营通知】添加联系方式 - {company_name}"
        include: ["公司名称", "对方要求的联系方式"]
      - type: "error"
        subject: "【自动运营异常】{error_type} - {date}"
        include: ["错误详情", "影响范围"]
      - type: "high_intent"
        subject: "【自动运营通知】高意向用户 - {platform}"
        include: ["用户昵称", "聊天摘要"]
  
  # 云手机异常通知
  error_triggers:
    - "云手机任务超时"
    - "云手机工具不可用"
    - "投递数量为0"
    - "执行报错或异常退出"
```

### 通知方式

使用 `email_request` 发送邮件通知。邮件内容要包含：
- 发生了什么事
- 涉及的公司/用户信息
- 需要用户做什么（如：需要自行回复HR问题）

## 任务调度

### 单次执行

用户手动触发时，直接按上述流程执行。

### 定时执行

使用 `calendar_create` 创建定时任务：

```
求职投递：每天执行一次
- dtstart: 工作日开始时间（如 09:00）
- rrule: freq=DAILY

社交运营：每N分钟执行一次
- dtstart: 运营开始时间
- rrule: freq=MINUTELY, interval=45
- time_range: 08:00-24:00
```

### 防重复执行

每次执行前检查 `sessions_list`，如果已有同类任务在运行，跳过本轮。

---

## 异常处理

| 异常类型 | 处理方式 |
|---------|---------|
| 云手机不可用 | 发邮件通知用户 + 记录日志，等待恢复 |
| 任务超时 | 拆分为更小的子任务重新执行 |
| App 界面变化 | 停止操作 + 通知用户 + 记录变化细节 |
| 岗位/用户质量低 | 调整筛选阈值 + 记录日志 |
| 重复操作 | 强化去重检查 + 记录已处理项 |

## 配置文件模板

配置文件存放在 `./autopilot_configs/` 目录下。参考本技能的 `configs/job_config_template.yaml` 和 `configs/social_config_template.yaml` 模板创建。

每个配置文件的结构包含：
- `platform`: 目标平台信息
- `identity`: 运营身份配置
- `scoring`: 打分规则（求职场景）
- `filters`: 过滤规则
- `reply_rules`: 回复规则（社交场景）
- `notifications`: 通知配置
- `privacy`: 隐私保护规则
- `schedule`: 调度配置

---

## 注意事项

1. **安全优先**：宁可漏投/漏回复，也不要违规操作或暴露隐私
2. **状态必更新**：每轮执行后必须更新状态文件，这是防重复的基础
3. **分阶段执行**：复杂任务拆成多个阶段，每阶段独立完成后汇报
4. **不自动回复 HR 问题**：求职场景中，HR 的提问一律通知用户自行回复
5. **控制频率**：打招呼、发消息都有频率限制，超限会被平台处罚
6. **先读状态再操作**：每次执行前先读取状态文件，避免重复操作
