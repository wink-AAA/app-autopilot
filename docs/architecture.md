# 架构设计文档

## 概述

App Autopilot 采用分层架构设计，将自动化运营的核心逻辑抽象为可复用的框架组件。每个层负责一个明确的职责，层与层之间通过清晰的接口交互。

## 架构层次

```
┌──────────────────────────────────────────┐
│           配置层 (Configuration)          │
│  YAML 配置 → Pydantic 模型 → 验证        │
├──────────────────────────────────────────┤
│           调度层 (Scheduling)             │
│  定时触发 → 任务编排 → 多阶段流水线      │
├──────────────────────────────────────────┤
│           决策层 (Decision)               │
│  打分引擎 → 规则匹配 → 消息分类          │
├──────────────────────────────────────────┤
│           保护层 (Protection)             │
│  隐私保护 → 信息隔离 → 脱敏检查          │
├──────────────────────────────────────────┤
│           适配层 (Adapter)                │
│  平台抽象接口 → 适配器注册 → 统一操作    │
├──────────────────────────────────────────┤
│           状态层 (State)                  │
│  JSON 存储 → 去重 → 排除名单 → 状态跟踪  │
├──────────────────────────────────────────┤
│           通知层 (Notification)           │
│  事件路由 → 多渠道投递 → 模板渲染        │
└──────────────────────────────────────────┘
```

## 核心模块详解

### 1. 配置系统 (`core/config.py`)

配置系统采用**分层继承**设计：

```
base.yaml (基础默认值)
    ↓ 继承 + 覆盖
job_hunter.yaml (场景配置)
    ↓ 环境变量覆盖
运行时配置 (AppConfig)
```

- 使用 **Pydantic v2** 进行类型验证
- 支持 YAML 文件的深合并（deep merge）
- 环境变量以 `APP_AUTOPILOT_` 为前缀进行覆盖

### 2. 打分引擎 (`core/scoring.py`)

打分引擎是一个**通用的多维度加权评分系统**：

- **维度（Dimension）**：每个维度代表一个评价角度（如薪资、城市、岗位匹配度）
- **权重（Weight）**：每个维度有权重乘数，影响最终得分
- **规则（Rule）**：每个维度下有多条评分规则，支持 `exact`、`range`、`contains`、`regex`、`in_list` 五种类型
- **硬性条件**：标记为 `is_hard_requirement=True` 的维度，得分为 0 时直接淘汰

打分流程：
```
候选数据 → 遍历维度 → 计算每个维度的规则得分 → 乘以权重 → 求和
         → 检查硬性条件 → 检查最低分阈值 → 通过/淘汰
```

### 3. 状态管理 (`core/state.py`)

状态管理采用 **JSON 文件存储**，设计原则是零依赖、轻量级：

- **集合（Collection）**：数据按集合组织，如 `applications`、`contacts`、`exclusions`
- **原子写入**：先写入临时文件再原子替换，防止写入中断导致数据损坏
- **去重机制**：通过 `dedup_key_exists()` 基于关键字段组合检查重复
- **排除名单**：内置排除名单管理，支持按类型过滤

### 4. 任务编排器 (`core/task_runner.py`)

任务编排器实现**多阶段流水线**模式：

```
Stage 1: 浏览 → Stage 2: 打分 → Stage 3: 投递 → Stage 4: 通知
```

特性：
- 阶段间通过 `context` 字典传递数据
- 每个阶段独立重试（可配置次数和间隔）
- 失败后的回退（fallback）机制
- `skip_on_failure` 控制是否因前置失败跳过后续阶段

### 5. 规则引擎 (`rules/matcher.py`)

规则引擎提供**可组合的匹配/过滤能力**：

- **Rule**：单条匹配规则，支持 14 种操作符
- **RuleSet**：规则集合，支持 AND/OR 逻辑组合
- **Matcher**：高层过滤器，支持 `include`/`exclude` 模式

### 6. 消息分类器 (`rules/classifier.py`)

消息分类器基于**关键词 + 正则**进行分类：

- 每个分类规则可绑定一个动作（通知/自动回复/忽略/标记/转发）
- 支持优先级排序（高优先级规则优先匹配）
- 支持自定义分类函数扩展

### 7. 隐私保护 (`rules/privacy.py`)

隐私保护模块提供三层防护：

1. **敏感数据脱敏**：自动替换文本中的敏感字段值
2. **信息隔离规则**：按场景（context）控制哪些信息不能暴露
3. **人设管理**：为不同平台维护不同的公开身份

### 8. 平台适配器 (`adapters/`)

适配器层定义了统一的操作接口：

```python
class PlatformAdapter(ABC):
    async def setup(config)        # 初始化
    async def browse(**kwargs)     # 浏览内容
    async def interact(action, id) # 执行交互
    async def read_messages()      # 读取消息
    async def send_message(...)    # 发送消息
    async def post_content(...)    # 发布内容
    async def teardown()           # 清理资源
```

适配器注册表（`AdapterRegistry`）支持：
- 手动注册适配器类
- 通过模块路径动态加载
- 根据配置实例化适配器

### 9. 通知系统 (`notifications/`)

通知系统采用**路由 + 渠道**模式：

- **NotificationPayload**：统一的通知内容格式
- **NotificationChannel**：通知渠道抽象基类
- **NotificationRouter**：根据事件类型路由到不同渠道

## 数据流

```
┌─────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ 调度器   │────→│ 任务编排  │────→│ 打分引擎  │────→│ 状态存储  │
│         │     │          │     │          │     │          │
└─────────┘     └────┬─────┘     └──────────┘     └──────────┘
                     │
                     ▼
              ┌──────────┐     ┌──────────┐     ┌──────────┐
              │ 平台适配器│────→│ 隐私保护  │────→│ 通知系统  │
              │          │     │          │     │          │
              └──────────┘     └──────────┘     └──────────┘
```

## 设计原则

1. **框架优先**：所有平台特定逻辑通过适配器注入，框架层保持通用性
2. **配置驱动**：行为通过 YAML 配置控制，无需修改代码
3. **零数据库依赖**：状态管理使用 JSON 文件，降低部署门槛
4. **渐进式复杂度**：简单场景只用核心模块，复杂场景按需启用高级功能
5. **安全默认**：隐私保护默认开启，敏感信息默认脱敏
